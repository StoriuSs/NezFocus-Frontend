# Making it yours

You have cloned the starter and it runs. Before you write your own code,
there is a pass of renaming to do — and it is worth doing **now**, because
some of these names end up in Docker volumes and container names where
changing them later is more annoying than it should be.

The list is short. The backend half has its own, longer one.

- [1. The project name](#1-the-project-name)
- [2. What the user sees](#2-what-the-user-sees)
- [3. The environment file](#3-the-environment-file)
- [4. The repository itself](#4-the-repository-itself)
- [5. Things you can leave alone](#5-things-you-can-leave-alone)
- [Check it worked](#check-it-worked)

Pick one name and use it everywhere: lowercase, hyphenated. Below it is
**`myapp`**.

## 1. The project name

```bash
grep -rl "react-starter" docker-compose.dev.yaml docker-compose.prod.yaml deploy.sh .env.example package.json \
  | xargs sed -i 's/react-starter-auth/myapp-web/g; s/react-starter/myapp-web/g'
```

On macOS, `sed -i ''` instead of `sed -i`. The first substitution catches the
names with `-auth` in them (`react-starter-auth-dev`,
`react-starter-auth-prod-app`), so none is left as `myapp-web-auth-…`.

That covers:

| Where | What it is |
| --- | --- |
| `name:` in both compose files | The Compose project — it decides **volume and network names** |
| `container_name:` in both | Cosmetic, until you run two projects on one machine and Docker refuses the second |
| The image name: `DEPLOY_IMAGE`'s default in `docker-compose.prod.yaml`, `deploy.sh` and `.env.example` | The three must agree: `deploy.sh` passes its own default to compose. If a server already has `DEPLOY_IMAGE` in its `.env.production`, change it there too |
| `package.json` `name` | |

Check it still parses:

```bash
docker compose -f docker-compose.dev.yaml config --services
```

## 2. What the user sees

These are the ones people notice, and the ones most often forgotten:

- **`src/config/site.ts`** — the product name, `name`: the browser tab
  (`<title>`, written into `index.html` at build time), the logo, and
  `{{appName}}` in any translation.
- **`index.html`** — the `lang` attribute, if your default is not English.
- **`public/`** — the favicons (`favicon.svg`, `favicon-32.png`, `apple-touch-icon-180.png`, copied from `design/assets/brand/` and named in `index.html`).
- **`src/i18n/locales/en/*.json` and `vi/*.json`** — the page copy. If you do
  not need Vietnamese, delete `vi/`, and remove it
  from `resources` and `supportedLngs` in `src/i18n/index.ts`, from
  `LanguageToggle.tsx`, and from `src/i18n/__tests__/catalogues.test.ts`.
  For another language, see [i18n.md](./i18n.md#adding-a-language).
- **The emails** — the API sends them, so their wording and product name are
  in the API starter.
- **`src/index.css` and `tailwind.config.js`** — the design tokens, generated
  from `DESIGN.md`. Change them there, not here alone
  ([theme-system.md](./theme-system.md)).

## 3. The environment file

In `.env.development`, and later `.env.production` on the server:

| Setting | Change it to |
| --- | --- |
| `VITE_API_URL` | Your API, **including** `/api/v1` |

That is the only required setting. Error tracking is optional; see the
reference. There are no sign-in settings here: Google sign-in is turned on in
the API, which also needs this app's address in its
`CORS_ORIGINS` and `FRONTEND_URL`.

The full reference, including what is read at build time versus container
start, is [environment.md](./environment.md).

## 4. The repository itself

- **`README.md`** — the title, the description, the badges.
- **The paired-repository link** in `README.md` and `OVERVIEW.md`, if you are
  not using the NestJS starter.
- **`git remote set-url origin …`**, and consider `rm -rf .git && git init`.
- **A `LICENSE`** — the starter has none. Add the one you choose before you
  publish, and say so in `README.md`.
- **`e2e/`** — the Playwright tests check the headings and button names of
  the pages they visit. Update them when you rename those, or delete them if
  you will not run them ([e2e-testing.md](./e2e-testing.md)).
- **`docs/`** — written about this starter. Edit as your project diverges.

## 5. Things you can leave alone

- **The CI image name** — derived from `GITHUB_REPOSITORY`, so it follows your
  repository.
- **`SITE_NAME` in `nginx/bootstrap-nginx.sh`** (`react-app`) — only matters
  with more than two projects on one host; pass `--site-name` then.
- **`nginx.conf`** — the cache headers and deep-link fallback are not
  project-specific.
- **The Content-Security-Policy** — generated by `scripts/csp.mjs` during
  the build and filled in with your addresses at container start by
  `nginx/40-runtime-config.sh`. Edit `scripts/csp.mjs` only when the app
  starts using a new outside service.
- **`FRONTEND_PORT`** — `8081` by default, bound to `127.0.0.1`. Only change
  it if something else on the server wants that port.

## Check it worked

```bash
pnpm install
cp .env.example .env.development     # then set VITE_API_URL
pnpm dev                             # http://localhost:3001
pnpm test && pnpm lint && pnpm build
docker compose -f docker-compose.dev.yaml config --services
```

To sign in, create an account on `/register`; with the API's development
stack, the code arrives in Mailpit at http://localhost:8025
([auth/README.md](./auth/README.md)). If a page's requests to the API fail,
it is `VITE_API_URL`, or the API's `CORS_ORIGINS` not naming
`http://localhost:3001`.
